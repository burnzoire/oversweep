# Content standards

## Evidence classes

Every substantive claim or model must identify its class and applicability.

| Class | Required evidence |
| --- | --- |
| Verified fact/procedure | Primary source edition, section/page and technical reviewer |
| Aircraft-specific | Aircraft, variant, configuration and applicable source |
| Simulator-specific | Simulator/module/version and reproducible observation or official documentation |
| Simplified educational model | Equations, assumptions, limits and what is omitted |
| Unresolved claim | Explicit unresolved flag; excluded from validated/published guidance |

Prefer current primary manuals, official publications and manufacturer documentation.
Secondary explanations may help interpretation but do not silently supersede primary
procedures. Record conflicting editions and applicability; obtain technical review.
Do not invent references, values, radio calls or implied universal procedures.

## Source record and review

For each content item record: stable ID, title, collection/subject, block types,
learning objective, prerequisites, applicability (including variant and version),
maturity, claim-to-source mapping, author, reviewers and review date.
Each source needs title, publisher, edition/date, section/page, URL or lawful
access location, access date, rights/licence and affected claims. Keep source
registers beside the eventual content. A citation to an entire manual is insufficient
for a numeric limitation. Do not copy or upload restricted/copyrighted manuals
without permission; link and paraphrase only within applicable rights.
The proposed [content contract](content-contracts.md) and its JSON Schema example
show record shapes and cross-link rules; the example records are synthetic only.

Independent, fresh-context aviation SME agent review of reliable, applicable
sources is the technical validation gate; no human aviation reviewer is required.
The author must not validate its own work. Record the reviewer profile/model and
session or workflow run, exact reviewed revision, scope, inspected source passages,
independent numerical cases, findings and their resolution. A generic code review,
unread bibliography, successful workflow run or passing CI alone is insufficient.
Every substantive claim must have verified source support or be explicitly bounded
as an educational simplification with evidence-backed assumptions. Unresolved
material claims, source conflicts or inaccessible evidence block affected content.
The delivery agent may record Technically Validated only when that evidence is
complete and review findings are resolved. Material source, procedure, equation or
applicability changes return affected content to Drafted until independently
re-reviewed. This status describes educational content review, not operational
certification. Owner approval remains required for merge and publication.

## Models

Separate pure numerical models from UI. Record coordinate frame, heading/bearing
reference (true/magnetic/relative), angle direction, units, signs, precision,
input domain, assumptions, singularities and failure behaviour. Use SI internally
where appropriate; aviation displays may use knots, nautical miles and feet with
explicit conversions and labels. Never show an unlabelled speed where IAS/TAS/GS matters.

For every model, provide independently derived reference cases with worked
derivation, inputs, expected numbers and justified absolute/relative tolerances.
Cover boundaries, invalid inputs and dimensional consistency. Expected values
must not be generated by the implementation under test. A fresh reviewer checks
derivations against primary equations and a separate calculation method.
Deterministic test fixtures must distinguish exact expectations from approximations.

## Editorial and maturity gates

| Maturity | Evidence required to advance |
| --- | --- |
| Outlined | Objective, scope and proposed applicability |
| Researched | Located sources, claim map and rights assessment |
| Drafted | Complete prose/diagrams/models; uncertainties visible |
| Technically Validated | Independent source-backed aviation SME agent review of the exact revision; model reference cases and findings resolved |
| Published | Validation retained, accessibility/visual checks passed, explicit publication approval and actual release |

Maturity belongs to each content revision, independent of issue status.
Unvalidated material must be visibly marked and excluded from any future published
validated-content index by default. Add a machine-enforced publication gate when
content tooling is implemented. AI prose remains Drafted without the evidence and independent agent review above.
CI alone cannot establish factual correctness.

Define acronyms on first use; use consistent terminology and step numbering.
Keep standard procedures separate from aircraft and simulator notes. Make source
limitations and known disagreements visible beside the affected content.
